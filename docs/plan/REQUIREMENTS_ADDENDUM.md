# Дополнение требований: защита силуэта, ComfyUI и инженерный процесс

Согласование от 11 ноября 2026 года с [исходными требованиями](../../LoRA_Dataset_Studio_Requirements.md).
Это обязательная часть действующего плана. S06 остаётся промежуточным ручным маршрутом; полная версия требует S08a и S09a.

## R1. Решения по расхождениям

- Сохраняются Vue 3/TypeScript, Laravel, PostgreSQL, Python worker, Fastify/Socket.IO, Docker Compose.
- Redis/Horizon, MinIO/S3, отдельный Python FastAPI — предложенные варианты, а не автоматически принятые замены. Первый выпуск использует текущую очередь и локальное хранилище. Переход требует ADR с причиной, миграцией и проверками отказов. Horizon имеет смысл только при выборе Redis.
- PHP 8.4/Laravel 13 из требований — кандидаты для проверки совместимости на S00, а не уже проверенные версии.
- Qwen3-VL добавляется к кандидатам Qwen3.5 для сравнения на реальной 16 GB GPU. Выбор модели/квантования/vision encoder фиксируется измерением, названия не гарантируют поддержку установленным LM Studio.
- Для character-набора два реальных человека остаются причиной исключения. Выбор целевой маски помогает анализу, но не разрешает экспорт такого изображения. Исправление ложной детекции требует причины. Более широкий режим нескольких персонажей — отдельное будущее решение.
- Локальный single-owner режим сохраняется. Все коллекции и скачивания проверяют владельца; многопользовательский вход/регистрация не являются заявленной готовой функцией.
- Не создавать встроенного AI-ревьюера. Учебное сопровождение — способ выполнения задач внешним наставником.
- Фото, аниме, 3D используют сменные CV-адаптеры. Непроверенный домен получает ручную проверку, а не фиктивную поддержку.

## R2. Защищённая область и планирование

1. Работать в единой системе координат после EXIF-нормализации; сохранять размеры и преобразование к оригиналу.
2. Детекция лица недостаточна: сегментировать весь видимый силуэт, включая волосы, одежду, кисти, стопы, аксессуары, хвост/крылья при наличии. Поза и лицо — вспомогательные признаки. Невидимые части не восстанавливать.
3. Создать версионированную бинарную маску и защищённую область с настраиваемыми отступами. Пользователь может добавить/стереть маску и выбрать ошибочно распознанную область. Низкая уверенность требует подтверждения.
4. До crop математически проверить включение всей защищённой области в выбранный прямоугольник. Нельзя обрезать видимую часть даже при сохранённом лице. Проверять также окончательный crop тренера.
5. Порядок: сохранить пиксели → безопасно обрезать лишний фон → пропорционально уменьшить → выбрать другой разрешённый bucket → расширить фон → ручная проверка. Непропорциональный resize и автоматический upscale запрещены.
6. Если часть тела касается границы исходника, направление расширения через эту границу автоматически блокируется. Если допустимый холст так получить нельзя — другой bucket либо ручная проверка; не обходить ограничение промптом.
7. Сохранять исходный фон. Маска не используется для удаления/замены фона, cutout или улучшения лица.
8. Planner возвращает варианты с причиной, crop, scale, canvas, offset, разрешёнными направлениями и долей новых пикселей. Для точного размера нельзя молча выбрать другой формат.
9. Процент генерации = новые пиксели / площадь итогового холста. Предел задаётся профилем и хранится в версии; при его превышении автоматический запуск запрещён. Пока порог не откалиброван, запуск требует явного подтверждения preview.
10. Любое изменение маски/геометрии инвалидирует downstream QA и captions. Ручные captions сохраняются, но требуют повторного утверждения.

## R3. ComfyUI и проверка результата

ComfyUI на первом этапе — внешний сервис на Windows/хосте, как LM Studio. Python обращается через адаптер; Laravel остаётся владельцем задачи и результата.
URL задаётся в UI, проверка выполняется из контейнера. Проверить достижимость, совместимость закреплённого workflow и наличие требуемых узлов/моделей; успешный HTTP сам по себе не означает готовность.

- Разрешены только заранее зарегистрированные версионированные workflow. Не принимать произвольный workflow/путь файла из браузера.
- Записать workflow hash, версии узлов/моделей, seed, параметры, внешний ID задания, времена и ошибки. Seed не является гарантией побитовой повторяемости на другом runtime.
- Общий GPU-slot распространяется на CV, LM Studio и ComfyUI во всех коллекциях. Сериализация запросов не освобождает VRAM резидентных моделей: необходимы явный план загрузки/выгрузки и проверка памяти; при невозможности — остановка с понятной инструкцией. Не выгружать чужую модель молча.
- Передать холст и маску только новых областей; исходная область не разрешена к генерации. После получения результата детерминированно вернуть все сохранённые пиксели, включая исходный фон.
- Если было уменьшение, эталон проверки — сохранённый результат этого детерминированного ресемплинга. Сравнить декодированные пиксели с эталоном, а не байты файлов. Промежуточный принятый результат хранить lossless; цветовое пространство и alpha policy фиксировать.
- Проверить размеры, масштаб, покрытие маски и точное равенство сохранённой области. Несовпадение — блокирующая ошибка; ручное одобрение не отменяет ошибку целостности.
- Отдельно проверить новые области на людей, продолжение тела и артефакты. Детектор/VLM не гарантируют семантическую правильность. В первой версии каждый outpaint проходит ручную проверку до экспорта; подозрительный результат нельзя автоматически принять.
- Результат: принять, отклонить, повторить с новыми параметрами. Повтор создаёт новую попытку/производную. Caption формируется после финальной композиции и QA.
- При разрыве связи искать состояние по сохранённому внешнему ID. Если отправка могла пройти, но ID неизвестен, состояние external_unknown: не отправлять дубль вслепую, не освобождать GPU до reconciliation.
- Отмена локальной задачи не доказывает остановку ComfyUI. Прерывать только собственное задание, когда адаптер умеет адресную отмену; общий interrupt нельзя применять к чужой работе. Поздний результат отменённой попытки не публиковать.
- Прогресс внешнего workflow показывать только при наличии достоверного total; иначе этап/прошедшее время. Он проходит Laravel/outbox и прежний Node gateway.

## R4. Редактор и экспорт

Редактор показывает отдельные переключаемые слои: исходник, силуэт, защитный отступ, crop, сохранённая область, новая область, финальная геометрия тренера.
Нужны кисть/ластик маски, undo/redo, zoom/pan, синхронное до/после, направления расширения, доля генерации, параметры и причина отказа planner.
Редактирование маски использует optimistic version; при конфликте локальные правки сохраняются.
Очередь проверки фильтруется по причинам: неполная маска, риск продолжения тела, новая фигура, неподтверждённая генерация.
Настройки ComfyUI отображают проверку соединения, workflow, модели, память и измеренную доступность без выдуманного процента.
Проекты/коллекции можно архивировать и вернуть из архива; архивирование не удаляет изображения и не равно корзине.

Preflight блокирует выбранные результаты без актуального QA/ручного утверждения outpaint, несохранённую маску и несовпадение пикселей.
Не включать needs_review только по подтверждению общего предупреждения. Можно исключить проблемный кадр и повторить preflight.
Manifest хранит mask/transform/QA/review revisions, workflow/model hashes, seed, retained rectangle, scale, generated_area_ratio и происхождение.
README экспорта описывает профиль, структуру, обработку и ограничения. Данные о генерации не скрываются от пользователя.

## R5. Инженерная поставка и учебная работа

S00: ADR в docs/decisions/ для границ сервисов, очереди, storage, GPU и спорных требований; docs/architecture/ с диаграммой и контрактами.
Каждая задача содержит ID, цель, prerequisites, входы/выходы, ограничения, acceptance, DoD, материалы и 2–3 вопроса для самостоятельного анализа.
В учебном режиме пользователь выполняет задачу, наставник проверяет diff, объясняет приоритет замечаний и повторно проверяет исправления. Не включать режим ожидания ученика без его запроса.

S01: README с запуском/остановкой/миграциями, .env.example без секретов, scripts или Makefile для стандартных команд, seeders/fixtures.
CI: PHPStan/Larastan, форматирование, ESLint, TypeScript, PHP unit/integration, Vitest, Python unit/contract, сборка; Playwright для доступного сквозного пути начиная с S06.
GitHub Actions включать при размещении проекта на GitHub; те же команды работают локально. Настройка CI не означает разрешение публикации/деплоя.
GPU-тесты отдельным явным профилем: CPU CI использует помеченные fixtures/mocks, не скачивает гигантские модели и не объявляет реальный inference проверенным.

S10: JSON-логи всех сервисов с correlation/job/attempt IDs; метрики глубины/возраста очереди, latency этапов, retries, ошибок, unknown-заданий, outbox lag и диска.
Не помещать изображения, captions, токены и исходные ответы модели в общие логи. Сырой ответ VLM хранить защищённо с историей caption и правилами очистки.
Различать liveness, readiness и доступность внешних AI. Диагностический отчёт редактирует секреты. Prometheus/Grafana опциональны.
Проверить MIME/сигнатуры, лимиты декодирования, traversal, доступ к чужому ID и скачиванию. ZIP-импорт не добавляется автоматически; если появится, нужны лимиты распаковки/количества файлов и защита от zip bombs.
AI по умолчанию локальные; внешние облачные endpoints требуют явного выбора с показом адреса назначения.
Dataset Quality Dashboard: сводка дублей, разрешений, кадров/поз, пригодности, доли сгенерированных файлов и непроверенных результатов; строится из сохранённых фактов.
