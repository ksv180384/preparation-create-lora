# Подготовка датасетов и интерфейс

Обязательные правила данных находятся в [DATA_MODEL.md](DATA_MODEL.md), API — в [CONTRACTS.md](CONTRACTS.md).
Все автоматические оценки сопровождаются источником, версией инструмента и возможностью ручной проверки.

## P1. Импорт и нормализация

1. Создать ImportBatch и показать отдельные элементы до начала отправки.
2. Загружать по одному файлу на HTTP-запрос, максимум 3 параллельно. Progress браузера показывает байты, скорость и передачу.
3. После передачи статус меняется на «Проверка на сервере». Это отдельная фоновая операция.
4. Сохранять оригинальное имя и relative_import_path; физическое имя строить по UUID/хешу, не по имени пользователя.
5. Сопоставлять image/TXT по относительному пути без расширения. Одинаковые имена в разных папках не смешивать.
6. TXT может прийти раньше изображения. Финализировать сопоставление после приёма пары или завершения импорта; непарные файлы показать пользователю.
7. Существующая подпись получает source=imported; у ImageAsset устанавливается base_caption_locked=true. При дубликате с другой TXT предложить конфликт, не затереть старую.
8. Retry использует тот же upload_key. Уже подтверждённый файл не отправлять повторно; после обновления страницы показать, какие файлы нужно выбрать заново.
9. На S05 поддержать JPEG, PNG и статический WebP; TXT UTF-8. Остальные форматы показать как неподдерживаемые. Расширение проверяется вместе с фактическим декодированием.
10. Начальные ограничения: 50 MiB на исходный файл, 50 мегапикселей после декодирования, ограниченная CPU-параллельность. Значения видны в настройках и уточняются после измерения RAM.
11. EXIF-поворот применяется к нормализованной копии. ICC преобразуется в sRGB; испорченный профиль создаёт предупреждение.
12. Оригинал сохраняется побайтно. Экспортная копия по умолчанию 8-bit RGB; для прозрачности пользователь выбирает фон с предпросмотром. Не отбрасывать alpha незаметно.
13. Анимации и многокадровые файлы не превращать молча в первый кадр. Для MVP — понятное исключение.
14. Миниатюры генерируются отдельно, без передачи оригинала на каждую карточку. Экспортные копии не наследуют GPS/лишние EXIF-поля.

Достаточность свободного места проверяется до партии, перед записью и перед экспортом. Учесть оригиналы, производные, staging и ZIP одновременно.
При нехватке места сохранить завершённое, остановить запись и показать объём, который требуется освободить.

## P2. Граф этапов обработки

Порядок по умолчанию:

    импорт → нормализация/миниатюры → технические проверки
    → точные дубли → CV/сходство → ручная проверка
    → предложенный набор → геометрия → подписи
    → финальная ручная проверка → preflight → ревизия → экспорт

Исключённые и заведомо повторные кадры не получают VLM-подписи по умолчанию.
«Описать всю коллекцию» — явная отдельная команда; предупреждение показывает число новых запросов и примерную длительность.

| Изменение | Что пересчитывается |
| --- | --- |
| Ручной текст caption | Только CaptionRevision и зависимые preflight/экспорты нового черновика |
| Crop/фон alpha | Производный кадр; подпись помечается stale/needs_review |
| Prompt или VLM | Только новые запрошенные подписи; locked подписи остаются |
| Детектор/порог | Анализ людей и рекомендации, без изменения исходников и ручного текста |
| Профиль тренера | Геометрия, профильные подписи при необходимости, preflight; исходный анализ переиспользуется |
| Выбор состава | Состав черновика и preflight |
| Новый исходный файл | Новая SourceFile/ImageAsset, не подмена старого файла |

Fingerprint = хеш канонического JSON входов: исходный/производный sha256, параметры этапа, revision инструмента/модели/профиля и prompt.
Ключи JSON сортировать; floating-point параметры сериализовать одинаково. Timestamp запуска не входит в fingerprint.
Кеш годен только при совпадении ключа и наличии целого артефакта. Отсутствующий файл — причина восстановления, а не успешного кеш-попадания.

## P3. Люди, идентичность и качество

- Детектор людей — отдельная локальная CV-модель. VLM не является единственным источником количества людей.
- На S08 сравнить кандидатов на реальных фото/рисунках; записать модель, лицензию, checksum весов, скорость, false positives/false negatives и выбранные пороги.
- При уверенном количестве >=2 в сценарии персонажа: excluded с кодом MULTIPLE_PEOPLE. В набор не включать.
- При низкой уверенности, отражении, коллаже, постере, сильной окклюзии или нуле детекций на портрете: needs_review.
- Показать bounding boxes и исходное решение. Исправление ложной детекции требует явного corrected_person_count и reason.
- Истинное наличие второго человека не «исправлять» автоматическим crop. По исходному требованию такой кадр исключается.
- В ручном маршруте до подключения детектора пользователь подтверждает количество и состав самостоятельно; интерфейс не показывает «проверено ИИ».
- Эталоны персонажа: рекомендовать 3–5 разных ракурсов, но разрешать работать без них.
- Сходство с эталонами показывает подозрительные кадры. Нет лица — не автоматический отказ. Порог для фото не переносить на аниме.
- Эмбеддинги не доказывают идентичность; в сомнительных случаях окончательное решение пользователя.
- Резкость/яркость/артефакты — объяснимые сигналы. Редкий полезный ракурс не отбрасывается только из-за меньшего «красивого» балла.
- Точный дубль определяется SHA-256; близкий дубль — только кандидат на групповую проверку.
- Изображения между коллекциями автоматически не объединять и не переносить.

Для калибровки нужна размеченная выборка, включающая сложные случаи. Пользовательские решения сохраняются отдельно от результатов модели.
Обновление модели не стирает ручные решения; показывает, где новые сигналы с ними расходятся.

## P4. Объяснимый отбор

Сначала применить пригодность: целостный файл, достаточное качество по проверенному профилю, принятый человек/персонаж, отсутствие жёстких исключений.
Затем учитывать ручные included/pinned. Закрепление не отменяет MULTIPLE_PEOPLE, повреждение или отсутствие файла.

Начальная реализуемая стратегия:
1. Сгруппировать точные/подтверждённые близкие дубли.
2. Выделить признаки покрытия: крупный план/по пояс/полный рост, профиль/анфас, поза, одежда, фон/свет. Источник признака — manual/CV/VLM/unknown.
3. Выбрать пригодные закреплённые кадры.
4. Добавлять представителей разных групп, закрывая недостающие категории; внутри категории использовать техническое качество и разрешение.
5. При равенстве использовать стабильный порядок по ID. Не вводить случайность без сохранённого seed.
6. Показать для каждого кадра причину включения/исключения и его вклад в покрытие.

Варианты: компактный — минимальный состав, покрывающий доступные ключевые категории;
сбалансированный — дополнительные полезные вариации; разнообразный — больше недублирующих ракурсов/условий.
Это разные предложения состава, пользователь может редактировать каждый. Если материала мало, варианты могут совпадать.
Ползунок размера ограничен количеством пригодных кадров. Не заполнять квоту дубликатами и не выдумывать недостающие ракурсы.

Рекомендация количества зависит от цели и данных. Ориентир 15–40 из руководства FLUX.2 Klein относится к описанному там сценарию, преимущественно стилю; не использовать его как обязательную норму персонажа.
Не обещать «лучшее число для архитектуры». Показывать диапазон, число уникальных групп и пробелы покрытия.
Веса/правила стратегии версионируются; пользователь видит рекомендации до подтверждения состава.

## P5. Геометрия и модельные профили

Первый универсальный профиль universal-image-caption-v1: нормализация, сохранение пропорций, без upscale и автоматического crop.
Максимальный размер задаётся явно; значение по умолчанию сохраняет исходное разрешение в пределах лимитов импорта.
Универсальный профиль не обещает отсутствие дополнительной обработки в неизвестном тренере.

Профиль тренера — неизменяемый JSON в profiles/ с полями:
profile_id, revision, task_kind, family, training_checkpoint/revision, inference_checkpoint/revision,
trainer/version_or_commit, status, verified_at, sources,
allowed_formats, resolutions/buckets, dimension_multiple, resize_policy, crop_policy,
upscale_policy, alpha_policy, caption_policy, config_template_revision, validation_evidence.

Статусы: unverified, experimental, verified, unsupported. Профиль становится verified только после проверки реальной конфигурации и геометрии.
Обновление создаёт новую revision. Существующие наборы не мигрируют автоматически.

| Семейство | Условие включения |
| --- | --- |
| FLUX.1 | Указать точный вариант; требования тренера проверяются отдельно |
| FLUX.2 dev | Отдельный профиль от Klein |
| FLUX.2 Klein 4B/9B | Отдельные размерности; training base и inference distilled записываются раздельно |
| FLUX.3 Image Klein | Отдельный профиль; не копировать параметры FLUX.2 |
| Z-Image Turbo | Явная стратегия training checkpoint/adapter и проверка применения к inference Turbo |
| Qwen Image | Обычный text-to-image профиль; Edit/Layered не включаются автоматически |

Первая проверяемая интеграция на S09 — FLUX.2 Klein base 4B + AI Toolkit, если установленная версия подтверждает нужный сценарий.
Если проверка не проходит, статус experimental и документированная причина; универсальный экспорт остаётся доступным. Остальные семьи добавляются независимыми адаптерами.

TransformSpec задаёт EXIF-normalized исходную систему координат, нормализованный crop [x,y,width,height] или null,
target dimensions, interpolation, alpha background, color conversion и profile revision.
Область «важное сохранить» задаётся пользователем или подсказкой CV, но сомнительный результат не принимается автоматически.

Предпросмотр «Как увидит тренер» воспроизводит resize/crop/bucket выбранной версии тренера.
Если нужно обрезать важную часть: выбрать другой допустимый bucket, вручную поправить crop или исключить кадр.
Padding допускается как явный выбор с предупреждением о полях в обучающих данных. Дорисовка/beautify/face restoration не включаются по умолчанию.
Не применять преобразование повторно и в студии, и тренере: владелец каждого шага записан в профиле и manifest.
После финализации геометрии captioning получает соответствующий кадр, а не случайную исходную миниатюру.

## P6. Подписи и RTX 4070 Ti Super

Стартовый кандидат: квантованная Qwen3.5 4B, GGUF для Windows. Сравнить Qwen3.5 9B на 10–20 файлах, если хватает памяти.
Не рекомендовать 27B штатно для 16 GB. Размер GGUF не равен суммарной VRAM; учитывать vision encoder, контекст, кеш и другие программы.
Если есть возможность оценки памяти LM Studio, показать её; не выдавать отсутствие телеметрии за свободную видеопамять.
Сравнивать время, выдуманные детали и объём ручных исправлений. Результат пробы сохраняется с параметрами.
16 GB — профиль подготовки данных, а не обещание вместимости обучения всех LoRA.

Язык TXT по умолчанию английский, UI русский.
Политика caption задаётся целью и тренером:
- character: trigger + класс объекта, видимые поза/одежда/кадрирование/окружение; обработка постоянных черт определяется явной настройкой шаблона и проверяется на пробе;
- clothing: описывать вариации носителя, позы и окружения, целевую одежду связывать с выбранным триггером;
- style: отдельный шаблон с контролем стилевых слов; не переносить character prompt автоматически.
Поддержать естественные предложения и теги, но не перемешивать форматы в одной генерации без выбранного правила.

Текст модели проходит проверки: не пустой, не обрезан, без служебных рассуждений/markdown, нужный язык/trigger согласно профилю.
Не добавлять невидимые детали. Почти одинаковые подписи — предупреждение, а не безусловный отказ.
Trigger вставляется/проверяется приложением по политике; повторную вставку не допускать.
Структурированные признаки могут быть JSON, экспортный TXT содержит только готовую подпись.
Список «готово к подписи» показывает новые, переиспользуемые, locked и stale результаты отдельно.

## P7. Preflight и экспорт

Preflight фиксирует версии состава, подписей, трансформаций и профиля.
Блокирующие ошибки: нет файла, битый результат, неподтверждённая пригодность, несколько людей, пустая обязательная подпись,
устаревшая после crop подпись, коллизия имени, неподдерживаемый формат/размер, недостаток диска, невалидная проверяемая конфигурация.
Предупреждения: низкое разнообразие, неопределённая совместимость универсального профиля, похожие captions, явный upscale/padding.
Пользователь может подтвердить предупреждения, но не игнорировать ошибки целостности.

Порядок публикации:
1. Проверить сохранённость UI-правок и expected draft version.
2. Зафиксировать снимок. Изменение исходного черновика после снимка не меняет его содержимое.
3. Создать DatasetRevision, если preflight соответствует именно этому снимку.
4. Создать Export job; собрать файлы в staging на том же filesystem, где итоговая папка.
5. Проверить хеши, пары, manifest и конфигурацию. Затем атомарно переименовать папку и поставить ready.
6. При сбое между rename и записью ready восстановиться по manifest; неполную папку не показывать готовой.

Экспортные имена стабильны и уникальны: порядковый номер + короткий ID; оригинальное имя остаётся в manifest.
TXT — UTF-8 с одинаковым basename изображения. Не менять оригиналы и другие версии.
manifest.json включает revision/profile IDs, training/inference модели, trainer commit, все хеши, transforms,
caption revisions, origin mapping, решения отбора, версии инструментов и подтверждённые предупреждения.
ZIP создаётся из конкретного готового экспорта. Конфигурации YAML/TOML генерируются только поддержанным адаптером; универсальная папка доступна отдельно.
Cache_directory тренера для разных экспортов задаётся раздельно, чтобы кеши не смешивали датасеты.

## U1. Экраны и поведение

| Экран | Обязательные действия и состояния |
| --- | --- |
| Библиотека | Создать/найти/переименовать коллекцию, счётчики, последние задачи, корзина |
| Исходники | Импорт файлов/папки, фильтры, сортировка, выделение, просмотр, существующие подписи |
| Проверка | Крупный кадр, эталоны/дубли рядом, рамки, причина, принять/исключить/исправить детекцию |
| Подготовленные наборы | Создать/сравнить наборы, профиль, trigger, pinned, crop, подписи, предложения |
| Экспорты | Версии, состав, path, размер, preflight, скачать ZIP, удалить/восстановить, редактировать как новую версию |
| Центр задач | Все коллекции, очередь, этапы, прогресс, ETA, pause/resume/cancel/retry-failed |
| Настройки | LM Studio, модели/проверки, корни хранения, лимиты, диагностика, backup |
| Корзина | Тип удалённого объекта, размер, зависимости, восстановление и отдельное окончательное удаление |

Переход между коллекциями сохраняет фильтр, прокрутку, размер карточек и выделение.
Виртуальная сетка + серверные фильтры/pagination + ленивые миниатюры. Оригинал загружается только в просмотрщике.
Просмотрщик: zoom/pan, следующий/предыдущий, синхронное до/после, рамка «видно тренеру».
Горячие клавиши не срабатывают при вводе текста; действия имеют обычные кнопки и доступные подписи.

## U2. Массовые операции и автосохранение

- Видно «выбрано 20» или «все 500 по фильтру». Перед операцией фиксируются ID и версии, а не живой изменяющийся фильтр.
- Предпросмотр diff/affected_count обязателен для массовой замены подписей.
- Режимы генерации показывают, какие locked/ручные подписи будут пропущены.
- Автосохранение имеет состояния «Есть изменения / Сохраняется / Сохранено / Конфликт / Ошибка».
- При конфликте локальный текст остаётся; пользователю доступно сравнение и повторное применение.
- Undo последнего решения/массовой правки создаёт новую ревизию и проверяет, что после неё не было конфликтующего изменения.
- Отсутствие socket-подключения не означает потерю HTTP-сохранения.

## U3. Прогресс и ошибки

Показывать раздельно: передано файлов/байтов, проверено, принято, выбрано, подготовлено, описано, экспортировано.
Не объединять эти числа в один непонятный «готово».
Для генерации без известного процента показывать spinner, время и этап; ETA по измеренным завершённым задачам помечен приблизительным.
ETA ожидания очереди и ETA выполнения различаются. После смены модели/параметров замер обновляется.
Одна сводка ошибок на задачу и раскрываемый список файлов; не выводить 500 одинаковых toast.
Системные слова lease/outbox/circuit breaker доступны в диагностике; основной UI говорит «Ожидание модели», «Повтор через…», «Нужна проверка».
Список ошибок включает filename, stage, cause, retryable, action и correlation_id. Успех соседних файлов остаётся виден.

## P8. Обязательное расширение: силуэт и фон

[REQUIREMENTS_ADDENDUM.md](REQUIREMENTS_ADDENDUM.md), R2–R4, уточняет P5:
