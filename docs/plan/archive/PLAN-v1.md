# План программы подготовки датасетов для LoRA

## 1. Цель

Локальное приложение для библиотеки LoRA-датасетов: у пользователя может быть много персонажей/коллекций, обычно около 500 исходных изображений на персонажа. Открывается в браузере по адресу localhost:7676. Для каждой коллекции можно отдельно анализировать, отбирать и готовить изображения.

Приложение готовит датасет, но не обучает LoRA. Оно должно работать локально и обращаться к установленной LM Studio через её API; отправка изображений или описаний во внешние облачные сервисы не входит в стандартный процесс.

## 2. Рекомендуемая архитектура

### Интерфейс

- **Vue 3 + TypeScript + Vite**: галерея, фильтры, просмотр карточек, редактирование подписей и панели заданий.
- **Node.js + Fastify + Socket.IO** — отдельный realtime-сервис для доставки прогресса и событий задач в интерфейс без перезагрузки страницы. Node.js также используется для сборки Vue.
- Vue подключается к Socket.IO через тот же origin `http://localhost:7676`; Nginx проксирует `/socket.io` к realtime-сервису. Отдельный порт Node не требуется открывать в браузере.

### Laravel backend

- **Laravel + PHP** — основной backend: REST API, коллекции персонажей, проверка загрузок, сохранение файлов, PostgreSQL-модели, экспорт, история заданий и ошибок.
- Laravel остаётся единственным владельцем схемы PostgreSQL и состояния заданий. Vue общается с backend через API на том же origin.
- Долгие операции не выполняются внутри HTTP-запроса. Laravel создаёт задание и элементы задания в PostgreSQL; Python worker получает работу через закрытые внутренние API Laravel и отправляет туда обновления прогресса/ошибок.
- Внутренние worker-маршруты доступны только внутри Compose-сети и защищены отдельным сервисным токеном. Python worker не меняет схему БД и не пишет в таблицы Laravel напрямую.
- После фиксации изменения состояния в PostgreSQL Laravel публикует событие во внутренний Fastify endpoint. PostgreSQL остаётся источником истины, Laravel владеет бизнес-логикой и состояниями, Node отвечает только за маршрутизацию realtime-событий подключённым клиентам; Python не пишет в БД напрямую.

### Realtime-события

- Fastify/Socket.IO запускается отдельным сервисом Docker Compose. Внутренний endpoint приёма событий доступен только сервисам в Compose-сети и защищён отдельным секретом; секрет не передаётся Vue.
- Для гарантии публикации после успешной записи состояния использовать transactional outbox на базе `JobEvent` (или отдельной таблицы outbox): записывать событие в той же транзакции PostgreSQL. Отдельный Laravel outbox-publisher отправляет его Node, хранит `attempt_count`, `next_attempt_at`, `published_at` и статус, повторяет временные ошибки с экспоненциальной задержкой и не удаляет застрявшие события: они видны в диагностике и доступны для повторной отправки. Повторная отправка безопасна; подтверждение Node означает приём события сервисом, но не доставку каждому браузеру.
- Конверт события содержит `event_id`, тип, `job_id`/`item_id` или `collection_id`, монотонную версию состояния, время и только нужные UI данные. Не передавать через Socket.IO изображения, секреты LM Studio, полные stack trace или большие payload.
- Socket.IO использует комнаты задач и коллекций. Сервер проверяет право доступа к комнате; клиент подписывается только на те задания/коллекции, доступ к которым подтверждён Laravel API. События не должны раскрывать данные других коллекций.
- Vue получает события вроде `job.updated`, `item.progress`, `item.completed`, `item.failed`, `upload.validated` и `export.updated`; после события обновляет соответствующее состояние/компоненты без перезагрузки страницы.
- WebSocket — канал быстрой доставки, а не хранилище. При первом открытии страницы, переподключении, пропуске версии/события и по явному обновлению Vue запрашивает актуальный snapshot через Laravel API. UI сверяет версии и игнорирует дубли/устаревшие события. При недоступности Socket.IO показывается понятный статус; REST/API продолжает работать, а для активных задач включается ограниченный fallback-polling snapshot через Laravel (например, раз в 3–5 секунд) до восстановления сокета.
- Для одиночного локального запуска достаточно одного Socket.IO-инстанса без Redis-адаптера. Масштабирование на несколько realtime-инстансов и внешний брокер отложить до появления такой потребности.

### Python worker

- **Python** выполняет CV/ML-задачи: проверку изображения, хеши дублей, детекцию людей, создание подписи через LM Studio, безопасное изменение размера и подготовку экспорта.
- Worker работает отдельным сервисом Compose и использует общую рабочую папку с Laravel для оригиналов, миниатюр и готовых изображений.
- Обработка каждого изображения и этапа фиксируется через Laravel API. Worker получает временную аренду задания с `lease_token`/сроком действия и продлевает её heartbeat-сигналом. Если worker пропал, Laravel повторно ставит задание в очередь после истечения аренды; устаревший worker с потерянной арендой не может записать результат. Этапы должны быть идемпотентными по fingerprint входа и настроек. Производные файлы сначала пишутся во временный путь и после проверки атомарно перемещаются на итоговый; оригиналы не изменяются. Временные ошибки можно повторить с задержкой, постоянные (например, повреждённый файл) показываются без бесконечных повторов. Один неудачный файл не останавливает всю коллекцию.

### PostgreSQL и Docker Compose

- **PostgreSQL** хранит много коллекций, изображения как записи/метаданные, подписи, статусы и устойчивую очередь заданий. Сами изображения хранятся в файлах, а не в БД.
- Docker Compose запускает сервисы: Nginx на localhost:7676, Laravel/PHP-FPM, отдельный Laravel queue/outbox publisher, Python worker, PostgreSQL и Node/Fastify/Socket.IO realtime-сервис. Nginx раздаёт Vue-сборку, проксирует API Laravel и `/socket.io` к Node; по умолчанию публикует порт только на loopback (`127.0.0.1:7676`), а доступ из локальной сети включается явно. Для разработки добавляется профиль с Vite dev-сервером.
- Постоянные volumes для PostgreSQL и библиотеки изображений сохраняются после пересоздания контейнеров. Предусмотреть резервное копирование БД и библиотеки с проверкой восстановления; не считать `docker compose down` способом резервирования. Код и рабочие данные рекомендуется держать в файловой системе WSL, а не на смонтированном Windows-диске.
- Для очереди Python-задач и outbox-publisher на первом этапе использовать таблицы заданий PostgreSQL и внутренний протокол Laravel; Redis/Kafka не добавлять, пока не появится измеримая потребность в отдельном брокере. Для контейнеров настроить restart policy и healthcheck готовности; проверять PostgreSQL, Laravel API, Python worker и Node отдельно. Недоступность внешней LM Studio отображать как состояние интеграции и не делать из-за неё всё приложение или Laravel API нездоровым.

## 3. LM Studio и модели

В интерфейсе будет раздел **Настройки → LM Studio** с полем базового API URL (вместе со схемой, хостом и портом), необязательным API-токеном и выбором модели. Для Docker Desktop предлагается начальное значение http://host.docker.internal:1234/v1, но пользователь может указать свой адрес. Laravel хранит настройки, токен — в зашифрованном виде, а Python worker получает их через закрытый внутренний API; секреты не попадают в журналы.

Кнопка **«Проверить подключение»** запускает проверку именно из Python worker: он будет обращаться к LM Studio при обработке изображений, и проверка должна подтвердить доступность из того же контейнера. Worker проверяет URL и авторизацию запросом GET /v1/models, измеряет время ответа и возвращает UI список доступных моделей. Интерфейс показывает понятный результат: подключено, тайм-аут, DNS/сетевой отказ, ошибка авторизации, неверный URL/API или недоступный список моделей; для исправимых ошибок выводится подсказка. Проверка запускается по требованию и после сохранения настроек, без ожидания начала обработки.

Доступность API сама по себе не подтверждает, что выбранная модель умеет анализировать изображения. Поэтому предусмотрена отдельная **проверка vision-модели** на тестовом изображении: Python worker отправляет изображение и короткий запрос через POST /v1/chat/completions; UI показывает результат или объясняет, что модель не загружена, не поддерживает изображения либо ответила ошибкой. Для endpoint, отличающегося от стандартного, URL остаётся редактируемым. В Docker Desktop начальным адресом обычно служит host.docker.internal; если LM Studio слушает только loopback и контейнер не может подключиться, интерфейс покажет шаги по настройке сетевого доступа и аутентификации. Приложение не включает доступ к сети автоматически.

### Рекомендация для описаний

- Для RTX 4070 Ti Super с 16 GB VRAM начать с vision-модели **Qwen3.5 4B** в квантованном варианте, доступном в LM Studio. Указанные каталогом 4 GB минимальной системной памяти — не требование к VRAM; фактический расход видеопамяти зависит от квантования, длины контекста, обработки изображения и загрузки других GPU-программ.
- Если качество 4B недостаточно, сравнить **Qwen3.5 9B** на 10–20 изображениях. Размер файла модели не считать оценкой расхода VRAM: перед загрузкой сверять ресурсную оценку LM Studio с доступными 16 GB и проверять реальное потребление с выбранным контекстом.
- **Qwen3.5 27B** не предлагать как штатный вариант для 16 GB VRAM. При желании пользователь может проверить его с частичной выгрузкой слоёв в RAM, понимая, что это может заметно замедлить обработку; перед загрузкой использовать оценку ресурсов LM Studio.
- Рекомендация по модели предварительная: перед массовой обработкой пользователь прогоняет 10–20 типичных изображений и выбирает вариант по точности и скорости именно на своём ПК.

Для 16 GB VRAM задать безопасный режим обработки: по умолчанию не более одного активного запроса к vision-модели LM Studio; CPU-этапы могут выполняться параллельно, а другие GPU-этапы Python не запускаются одновременно с caption inference без явного разрешения. Ограничивать размер отправляемого изображения и контекст настройками профиля; не передавать всю коллекцию одним запросом. При нехватке памяти/тайм-ауте ставить очередь на паузу, показывать причину и предлагать повтор после освобождения GPU. Перед массовой задачей провести замер на пробной группе; не считать все 16 GB свободными, если параллельно открыты ComfyUI, генерация или обучение. Приложение не меняет GPU offload и контекст LM Studio автоматически: показывает, загружена ли выбранная модель, и даёт инструкции/ссылку на оценку ресурсов LM Studio перед её загрузкой. На этой машине начать с квантованной Qwen3.5 4B; Qwen3.5 9B использовать только после проверки фактического запаса VRAM и качества. Для подготовки датасета LoRA-обучение не запускать.

- Вызовы LM Studio ограничивать тайм-аутами и одним активным запросом; для сетевых сбоев/временной недоступности применять ограниченные повторы с экспоненциальной задержкой и cooldown. При повторных сбоях открывать circuit breaker, ставить очередь на паузу и показывать действие пользователю; ошибки URL, авторизации, неподдерживаемого endpoint и повреждённого запроса считать постоянными до исправления настроек. Тайм-аут не должен запускать немедленный параллельный дубль запроса к GPU.

VLM описывает видимые детали, но не должен единолично решать, сколько людей изображено: такие ответы могут быть ошибочными. Для этого нужен отдельный локальный детектор людей с порогами уверенности. Сомнительные кадры получают статус «Проверить вручную», а не удаляются автоматически. Для аниме и стилизованных изображений точность детектора необходимо отдельно оценить на примерах пользователя.

### Формат описания

Генерировать одно короткое описание на английском языке по умолчанию, пригодное для Stable Diffusion. В описании указывать триггерное слово (если задано), вид персонажа, волосы/лицо, одежду, позу, кадрирование, фон и стиль изображения. Не дополнять кадр деталями, которых модель не может уверенно увидеть. Пользователь может выбрать более естественный текст или теги, задать язык, триггерное слово и шаблон.

## 4. Основной пользовательский процесс

1. **Создать коллекцию** и задать имя, тему LoRA, триггерное слово, точную целевую архитектуру и вариант модели (FLUX.1, FLUX.2 dev/Klein, FLUX.3 Image Klein, Z-Image Turbo или Qwen Image), профиль тренера и папку экспорта. Если для обучения нужен base/undistilled checkpoint, а LoRA планируется применять к distilled-варианту, хранить эти два выбора раздельно.
2. **Добавить изображения** через множественный выбор файлов или перетаскивание. При необходимости поддержать импорт всей папки. Загрузка идёт отдельными запросами по файлам с отображением прогресса и повтором неудачной передачи; интерфейс не отправляет все файлы одной монолитной загрузкой.
3. **Провести первичную проверку**: формат, размеры, EXIF-поворот, повреждённые файлы, точные дубликаты по хешу и близкие дубликаты по perceptual hash.
4. **Проверить пробную группу и запустить анализ.** Сначала дать прогнать 10–20 изображений, сравнить подписи, решения детектора, crop/размер и скорость; после подтверждения настроек запустить фоновый анализ всей коллекции. Этапы: качество и разрешение, число людей, видимость главного персонажа, VLM-описание и поиск похожих кадров. Показывать прогресс, ошибки по отдельным файлам, повторный запуск неудачных этапов и отмену задания.

5. **Просмотреть и исправить результаты** в галерее. Для каждого файла видны оригинал, миниатюра, метаданные, оценка, причина исключения/проверки и подпись.
6. **Выбрать набор** по рекомендации программы, вручную либо сочетанием обоих вариантов. Пользователь подтверждает итоговый состав перед экспортом.
7. **Подготовить изображения** с выбранным профилем обучения и создать папку экспорта с парами «изображение + `.txt`».

### Прогресс и отображение ошибок

- **Загрузка:** общий прогресс по переданным байтам и числу файлов, отдельный прогресс каждой загрузки, скорость и оставшееся время. После завершения передачи показывать отдельный статус серверной проверки/сохранения, чтобы переданные байты не выглядели как уже обработанные изображения.
- **Обработка коллекции:** общий прогресс задания и число завершённых изображений из общего количества; прогресс/этап каждого файла: очередь, проверка, поиск дублей, детекция людей, запрос к LM Studio, изменение размера, сохранение результата. Явно показывать ожидание слота LM Studio/GPU отдельно от времени фактической генерации подписи.
- **Оценка ожидания:** показывать прошедшее время и пересчитываемый приблизительный ETA по скорости последних файлов/этапов. Если надёжный процент/ETA ещё нельзя рассчитать (например, во время генерации подписи моделью), показывать анимированный неопределённый прогресс-бар, текущий этап и прошедшее время, а не выдуманный процент. Время ответа LM Studio может сильно меняться.
- **Экспорт и пакетные изменения** тоже показывают ход выполнения, успешные/пропущенные/ошибочные элементы и возможность открыть подробности.
- Прогресс и ошибки хранятся в PostgreSQL, поэтому сохраняются при обновлении страницы и перезапуске контейнера. В реальном времени Vue получает обновления через Socket.IO; при открытии страницы и переподключении загружает snapshot через API Laravel. Индикатор прогресса обновляется независимо от того, какая папка сейчас открыта.
- Для передачи файлов байтовый прогресс показывает браузер по состоянию отдельных HTTP-загрузок; Socket.IO сообщает о серверной проверке/сохранении, завершении и ошибках загрузки. Так прогресс передачи не смешивается с дальнейшей обработкой файла.
- UI показывает подключение/переподключение Socket.IO. При временной потере realtime-соединения задача продолжает выполняться; после восстановления интерфейс синхронизирует состояние с Laravel API и получает новые события.
- API прогресса возвращает job_id, item_id, stage, percent (если вычислим), completed/total, elapsed_seconds, eta_seconds (приблизительно), status, error_code, user_message, retryable и correlation_id. Для неопределимого процента поле остаётся пустым, а интерфейс показывает анимированный неопределённый прогресс-бар, текущий этап и прошедшее время.
- **Ошибки:** единый журнал ошибок для Laravel, Python worker, PostgreSQL и LM Studio. Понятное сообщение на русском, имя файла/коллекции, этап, код, время, можно ли повторить, и следующее действие. Показать сводку по всей задаче и список ошибок по отдельным файлам; успешные файлы не теряются из-за ошибки соседнего.
- Для ошибки доступны повтор только неудачных элементов и копирование технических сведений. Подробный trace и журналы остаются в логах; UI показывает безопасное краткое объяснение и идентификатор ошибки. Передавать единый `correlation_id` через Laravel, Python, outbox и Node, чтобы связать журналы одного задания; структурированные логи ротировать и очищать от токенов, секретов и лишнего содержимого запросов. Не скрывать исключения и не отмечать частично завершённую задачу как полностью успешную.
- Типовые причины: неподдерживаемый/повреждённый файл, нехватка диска, Laravel API или Python worker недоступен, PostgreSQL недоступен, LM Studio недоступна, модель не загружена или не принимает изображения, таймаут, ошибка детектора или нехватка VRAM/ошибка CUDA, недоступный путь экспорта. Для них показывать отдельное понятное действие.

## 5. Галерея и управление папками

- Боковая панель со списком коллекций/папок и счётчиками: всего, принято, исключено, требует проверки, экспортировано.
- Сетка миниатюр с виртуальной прокруткой, чтобы просмотр сотен файлов не перегружал страницу.
- Фильтры по статусу, оценке, числу людей, дубликатам, разрешению, формату и наличию описания.
- Отдельная очередь «Требует проверки», отсортированная по степени неопределённости; для дублей и похожих кадров показывать изображения рядом с причиной совпадения.
- Быстрые клавиши и пакетная обработка для принятия/исключения; принятое изображение можно закрепить, чтобы рекомендация не исключала его автоматически.
- Сортировка по имени, качеству, дате импорта, близости к дублю и рекомендации.
- Панель подробного просмотра с масштабированием и переходом к следующему/предыдущему изображению.
- Пакетные действия: принять, исключить, назначить статус проверки, запустить генерацию/перегенерацию подписи.
- Описание можно редактировать в панели или сразу в списке; изменения сохраняются автоматически с явным индикатором сохранения.
- Удаление доступно как для исходных элементов коллекции, так и для созданных экспортов. Сначала использовать корзину/мягкое удаление с возможностью восстановления; безвозвратное удаление — отдельным действием.
- Можно переключаться между исходной коллекцией и созданными экспортными папками, открывать экспорт и просматривать его изображения и подписи.

## 6. Отбор изображений и рекомендации

Система не должна просто брать изображения с самым высоким одиночным баллом. Она сначала отсекает технически негодные и дублирующие кадры, затем подбирает разнообразный набор.

### Автоматические сигналы

- целостность файла, ширина/высота и достаточность разрешения;
- размытость, слишком тёмный/светлый кадр и сильные артефакты с осторожными порогами;
- обнаруженные люди и уверенность детектора;
- доля кадра, занятая основным персонажем, и видимость важных частей;
- точные и близкие дубли;
- возможные пересечения с другими коллекциями/версиями персонажа — показывать предупреждение, но не переносить и не объединять изображения автоматически;
- повторяемость позы, ракурса, одежды и фона по визуальному сходству;
- разнообразие оставшегося набора по позам, кадрированию, фону и освещению.
- покрытие коллекции по планам и ракурсам (крупный план, по пояс, в полный рост, профиль/анфас), одежде и окружению; давать пользователю задавать желаемые минимумы без автоматического удаления других категорий.

Для спорного содержимого использовать состояния **«Принять»**, **«Исключить»** и **«Проверить вручную»**. Если уверенно найдены два и более человека, кадр по умолчанию исключается из рекомендуемого набора; решение можно проверить или переопределить вручную.

### Рекомендуемое количество

Показывать модельно-зависимый ориентир по размеру набора, а не универсальное число для всех архитектур. Для FLUX.2 Klein официальное руководство приводит 15–40 изображений в своём сценарии, но приложение должно считать рекомендацию эвристикой и пересчитывать её по разнообразию и качеству конкретной коллекции. Для FLUX.1/2, FLUX.3 Klein, Z-Image Turbo и Qwen Image выводить отдельный профиль и объяснение: сколько исключено как дубли/низкое качество/несколько людей, какие группы поз или ракурсов недопредставлены и сколько кадров предлагается взять. Ползунок размера набора и ручные исключения всегда доступны; финальный выбор подтверждает пользователь. Дополнительно показывать несколько вариантов состава — компактный, сбалансированный и максимально разнообразный — с визуальным сравнением групп и объяснением различий.

В MVP итоговый скоринг должен быть объяснимым: пользователь видит не только балл, но и причины — например, «похож на 8 кадров», «маленький персонаж в кадре», «детектор нашёл 2 человека». Автоматический отбор предлагается, но финальный состав подтверждает пользователь.

## 7. Изменение размера и экспорт

### Профили целевых архитектур

Целевые модели — FLUX.1, FLUX.2 (включая Klein 4B/9B), FLUX.3 Image Klein, Z-Image Turbo и Qwen Image. Для каждого профиля хранить точный идентификатор чекпойнта и ревизию, модельный вариант, тренер и его проверенную версию, требования к подписи и настройкам buckets, дату проверки совместимости и статус **«проверен / экспериментальный / не поддерживается»**. Актуальность матрицы поддерживать отдельно от кода обработки изображений: новые версии моделей и тренеров не должны незаметно менять уже сохранённые настройки экспортов.

В выборе профиля различать модель, на которой обучается LoRA, и модель, где она будет использоваться. Для FLUX.2 Klein и FLUX.3 Image Klein предусмотреть выбор base/undistilled checkpoint для обучения; отдельно записывать целевой вариант для инференса и проверять совместимость адаптера с ним по документации конкретной версии. Для Z-Image Turbo показывать выбранную стратегию обучения и необходимые компоненты/адаптеры конкретного тренера. Для Qwen Image и FLUX.2/3 Klein использовать отдельные архитектурные пресеты, не переносить параметры другого семейства автоматически.

Набор исходников и результаты отбора хранить независимо от профиля экспорта. Это позволит подготовить из одной коллекции несколько версий датасета: например, один экспорт для FLUX.2 Klein и другой для Qwen Image, со своими размерами, captions и файлами конфигурации. Общими остаются безопасное сохранение пропорций, отсутствие незаметного upscale и ручная проверка сомнительных crop.

Подписи настраивать под семейство модели и тренер: поддержать короткие теги и описательные предложения, неизменный trigger token, а также отдельные варианты шаблонов для персонажа, стиля и одежды. Перед экспортом валидировать, что trigger token присутствует согласно настройке тренера и что формат caption соответствует выбранному профилю. Проверять пустые и почти дублирующиеся описания, возможные противоречия между caption и видимым содержимым, а также показывать подпись рядом с изображением для ручной сверки. Для FLUX.3 Klein сохранять возможность подробных естественно-языковых описаний сцены; не навязывать такой формат всем моделям.

Экспортировать универсальные пары изображение + caption и дополнительно конфигурацию только для проверенных тренеров/версий (например, YAML для AI Toolkit или TOML для Musubi Tuner/sd-scripts, если профиль это поддерживает). В manifest сохранять точные идентификаторы модели обучения и инференса, профиль тренера и его версию, размеры/buckets, версию caption-шаблона, хеши исходников и применённые преобразования. Не выдавать экспериментальную конфигурацию за проверенную.

- Не обрезать изображения автоматически по центру. Сохранять исходное соотношение сторон и не отрезать голову/тело персонажа.
- Поддержать тренировочные профили и настройки размера для выбранной архитектуры и версии тренера. Разрешить aspect-ratio buckets там, где их поддерживает выбранный тренер; не использовать единый размер/crop для FLUX, Z-Image Turbo и Qwen Image. Конкретные buckets, лимиты разрешения и запрет upscale брать из проверенного профиля.
- По умолчанию создавать нормализованную копию с поворотом по EXIF, RGB-цветом и ограничением чрезмерно больших файлов, сохраняя пропорции. Оригинал остаётся нетронутым.
- Дополнительно предложить ручной crop с рамкой и безопасным полем вокруг персонажа; до/после показывать рядом.
- Если исходник очень мал, не увеличивать его незаметно: пометить и дать пользователю выбрать отказ от него или увеличение.
- Экспорт создавать в новой папке с понятным именем коллекции и версией, например `exports/character-v1/`. Внутри — изображения, одноимённые `.txt` captions и `manifest.json` с исходным именем, выбранным статусом и настройками обработки.
- Поддержать копирование в обычную структуру обучения и ZIP-архив. Экспорт не меняет исходники.
Перед публикацией экспорта выполнять preflight: проверить выбранный состав, поддерживаемость форматов, совпадение имён image/caption, отсутствие пустых captions и коллизий имён, целостность записанных файлов, достаточность места на диске и корректность конфигурации по схеме выбранного профиля. Показать отчёт с ошибками и предупреждениями. Собирать экспорт во временную папку и помечать его завершённым/перемещать на итоговый путь только после успешной проверки; при сбое оставить исходную коллекцию нетронутой и предложить повтор.

## 8. Данные и API (эскиз)

Основные сущности Laravel/PostgreSQL: Collection, ImageAsset, AnalysisResult, CaptionRevision, ProcessingJob, ProcessingJobItem, JobEvent (включая outbox-поля для доставки событий), Export и ExportPreflight. Worker взаимодействует с заданиями только через внутренние Laravel API: claim задания, progress, complete/fail. Публичный API включает коллекции, файлы, подписи, задания, ошибки и snapshots прогресса; миниатюры/файлы выдаются через защищённые Laravel-маршруты с проверкой корня хранения. Fastify предоставляет внутренний endpoint для приёма событий от Laravel и Socket.IO namespace/rooms для realtime-подписок браузера; он не становится владельцем бизнес-данных и состояния заданий.

Каждый этап анализа хранит fingerprint исходного файла и версию/хеш своих параметров: модель и ревизию VLM, prompt-шаблон, детектор, модельный профиль и настройки преобразования. Совпадающий этап можно повторно использовать. Изменение текста caption не запускает повторно детектор; изменение профиля экспорта пересобирает только нужные производные файлы; изменение исходника или версии детектора инвалидирует соответствующие результаты. У экспорта сохранять номер ревизии и diff состава/подписей относительно предыдущей версии.

Основные маршруты API: `GET/POST /api/collections`, `POST /api/collections/{id}/uploads`, `GET/PATCH/DELETE /api/images/{id}`, `POST /api/collections/{id}/analyze`, `GET /api/jobs/{id}`, `POST /api/collections/{id}/exports`, `GET /api/settings/lm-studio/test`. Изображения отдавать через отдельный endpoint миниатюр и безопасный файловый endpoint с проверкой путей.
- События для Socket.IO публикуются Laravel из transactional outbox во внутренний Fastify endpoint; браузер подключается к Socket.IO через Nginx на том же origin. Laravel API остаётся способом получить полный snapshot задания и восстановить состояние после переподключения; клиент не считает Socket.IO долговременным журналом.

## 9. Этапы разработки

### Этап 1 — проверка интеграции и профилей

- Проверить, как установленная версия LM Studio принимает изображение через выбранный OpenAI-совместимый endpoint.
- На выборке 10–20 файлов сравнить Qwen3.5 4B и доступную более крупную модель по точности описания, обнаружению нескольких людей и времени ответа.
- Проверить детектор людей на реальных типах изображений пользователя; определить пороги автоматического исключения и ручной проверки.
- Составить матрицу точных целевых вариантов FLUX.1, FLUX.2/Klein, FLUX.3 Image Klein, Z-Image Turbo и Qwen Image: доступность в выбранном тренере, checkpoint для обучения, формат captions/config, требования к памяти и статус проверки.
- Для каждого поддерживаемого профиля проверить экспорт на минимальной выборке: парность image/caption, валидность конфигурации выбранным тренером и короткий smoke-run, если GPU доступен.

### Этап 2 — локальный каркас

- Docker Compose каркас: Laravel/PHP-FPM, Laravel queue/outbox publisher, Nginx, PostgreSQL, Python worker и Node/Fastify/Socket.IO; Vue-сборка и персистентная библиотека файлов; запуск через localhost:7676. Настроить loopback-публикацию порта, healthchecks и restart policy, проксирование `/socket.io` через Nginx, внутреннюю аутентификацию публикации событий и проверку health/status realtime-сервиса.
- Импорт файлов с прогрессом, безопасное именование, миниатюры и список коллекций.

### Этап 3 — просмотр и ручная подготовка

- Галерея, фильтры, просмотр изображений, редактор описаний, статусы файлов, детальная панель ошибок и восстановление удалённых элементов. Добавить очередь ручной проверки, сравнение похожих изображений рядом и быстрые клавиши; дать закреплять принятые кадры.

### Этап 4 — анализ и подписи

- Внутренний API Laravel для worker, Python worker, очередь и transactional outbox в PostgreSQL, Laravel outbox-publisher, LM Studio, хеши дублей, детектор людей, captions, повтор ошибок и сохранение прогресса каждого элемента. Добавить аренду заданий с heartbeat и защитой от устаревшего worker, идемпотентные fingerprints этапов, атомарную запись производных файлов, классификацию временных/постоянных ошибок и отложенные повторы; ограничить одновременные обращения к LM Studio одной задачей по умолчанию.

### Этап 5 — рекомендации и обработка

- Отчёт о составе коллекции, диверсифицированный ранжированный отбор, понятные причины оценки, покрытие планов/ракурсов, варианты компактного/сбалансированного/разнообразного набора, профили разрешения и просмотр до/после.

### Этап 6 — экспорт

- Создание папки обучения и ZIP, парные captions, manifest и конфигурационный файл для проверенного профиля тренера; preflight-отчёт, сборка во временную папку и публикация только после полной проверки.

## 10. Критерии готовности первой версии

- Через Docker Compose можно открыть приложение по localhost:7676; создать много коллекций и импортировать не менее 500 файлов в каждую тестируемую коллекцию с видимым прогрессом.
- После перезапуска приложения коллекции, статусы, подписи и задания остаются на месте.
- В галерее можно переключать папки/экспорты, просматривать изображения, менять и сохранять описания, удалять и восстанавливать элементы.
- Очередь ручной проверки показывает спорные кадры и дубли рядом; решения принимаются с клавиатуры и групповых действий, закреплённые кадры остаются в наборе.
- Отчёт показывает покрытие коллекции по планам и ракурсам; доступны варианты компактного, сбалансированного и разнообразного набора и сравнение их состава.
- Повторная обработка переиспользует результаты этапов с совпадающими входными fingerprint и настройками; изменение одного этапа не запускает все остальные заново.
- Для каждой коллекции можно выбрать точную модель из списка FLUX.1, FLUX.2/Klein, FLUX.3 Image Klein, Z-Image Turbo и Qwen Image; экспортный профиль показывает проверенный тренер, требования к размеру/captions и статус совместимости.
- В интерфейсе можно задать и сохранить собственный URL LM Studio, необязательный API-токен и модель; URL не зашит в код и проверяется из контейнера Python worker.
- Проверка LM Studio отображает доступность API и модели из GET /v1/models, задержку и понятную причину ошибки; отдельная проверка vision-модели подтверждает анализ тестового изображения.
- Пользователь может выбрать vision-модель и создать описание для каждого принятого изображения.
- Дубликаты, низкое качество, один/несколько людей и неопределённые случаи видны в интерфейсе с объяснением статуса.
- Для поддерживаемых тренеров создаётся конфигурация, которую можно проверить выбранной версией trainer; непроверенные комбинации явно помечены.
- Перед публикацией экспорта UI показывает preflight ошибок/предупреждений; проверяются пары image/caption, коллизии имён, целостность файлов, место на диске и конфигурация профиля. Незавершённый экспорт не отображается как готовый.
- Экспорт содержит выбранные изображения с теми же базовыми именами и соответствующими `.txt` файлами; пропорции не искажены, исходники сохранены.
- Рекомендация по набору учитывает разнообразие и объясняет предложенное количество и исключения.

- Во время загрузки видны общий и файловый прогресс, скорость, ошибки передачи и серверной проверки.
- Во время обработки видны текущий этап, общий счётчик и состояние каждого файла; ETA показывается как приблизительное и пересчитывается.
- Ошибки не теряются: пользователь видит причину и действие, может повторить только неудавшиеся элементы; частичный успех показан явно.
- После обновления страницы прогресс и ошибки активных/завершённых заданий остаются доступны.
- При остановке Python worker аренда задачи истекает, задание безопасно возобновляется без повреждения уже сохранённых исходников и результатов.
- При недоступности Node события остаются в outbox, REST/API работает, UI включает ограниченный polling активных задач; после восстановления Node события доставляются повторно, а дубли не искажают состояние.
- Новые этапы и результаты задач приходят в Vue через Socket.IO без перезагрузки страницы; после переподключения состояние сверяется с Laravel API, а дубли/устаревшие события не портят прогресс.
- Загрузка файлов показывает байтовый прогресс HTTP, а серверные проверки/сохранение и ошибки отображаются отдельными realtime-событиями.
- При остановке Node realtime-сервиса UI ясно показывает потерю realtime-соединения, задачи продолжают сохранять состояние в PostgreSQL, ограниченный polling поддерживает видимый прогресс, а после восстановления интерфейс синхронизируется с Laravel API.
- При временной недоступности LM Studio очередь ставится на паузу с понятной причиной и ограниченным автоматическим повтором; вся коллекция не помечается ошибочной из-за одного сбоя интеграции.
- Панель состояния показывает доступность Laravel API, PostgreSQL, Python worker, Laravel queue/outbox publisher, Node/Fastify/Socket.IO realtime-сервиса и LM Studio и объясняет, что именно не подключено. Для PostgreSQL и библиотеки файлов описан и проверен сценарий резервного копирования/восстановления.
- Для RTX 4070 Ti Super 16 GB VRAM обработка по умолчанию ограничивает одновременную vision-генерацию одним запросом; очередь умеет ждать/ставиться на паузу при занятом GPU, timeout и нехватке VRAM.

## 11. Что уточнить перед реализацией

Подтверждённая видеокарта для исходного профиля — RTX 4070 Ti Super с 16 GB VRAM; объём системной RAM ещё уточнить. Для vision-captioning начать с квантованной Qwen3.5 4B, а Qwen3.5 9B включать после замера ресурсоёмкости и качества на этой машине. Перед точной матрицей экспорта нужно указать фактические варианты целевых моделей, выбранный тренер и его версию; также важно, преобладают ли фотографии или рисунки/аниме. Базовое предположение для запуска — Windows с WSL2 и Docker Desktop; URL LM Studio и расположение библиотеки остаются настраиваемыми.
