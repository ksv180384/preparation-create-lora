# План реализации локальной студии подготовки LoRA-датасетов

Редакция: 2.1, 11 ноября 2026 года. Учтены решения пользователя, AUDIT.md и LoRA_Dataset_Studio_Requirements.md.
Это спецификация будущей реализации. Наличие пункта в плане не означает, что он уже реализован.

## 1. Как работать с планом

Начинай каждую сессию реализации с этого файла и [PROGRESS.md](docs/plan/PROGRESS.md).
Затем прочитай свой этап в [STAGES.md](docs/plan/STAGES.md) и указанные там разделы спецификаций. Для небольшой задачи не нужно загружать в контекст историю чата и все будущие этапы.

| Документ | Что является его предметом |
| --- | --- |
| [DATA_MODEL.md](docs/plan/DATA_MODEL.md) | Сущности, ревизии, статусы, сохранность файлов и ручных изменений |
| [CONTRACTS.md](docs/plan/CONTRACTS.md) | HTTP API, worker, очередь, аренды, события, LM Studio и ошибки |
| [PIPELINE_AND_UI.md](docs/plan/PIPELINE_AND_UI.md) | Подготовка изображений, профили обучения, рекомендации, экраны и UX |
| [STAGES.md](docs/plan/STAGES.md) | Порядок реализации, небольшие задачи, проверки и критерии завершения |
| [PROGRESS.md](docs/plan/PROGRESS.md) | Фактическое состояние реализации, доказательства готовности и следующий шаг |
| [AUDIT.md](AUDIT.md) | Обоснование изменений; исторический аудит [предыдущей редакции](docs/plan/archive/PLAN-v1.md) |
| chat.md | История обсуждения; старые предложения не заменяют принятые ниже решения |

Правила для модели-исполнителя:

1. Выполняй один этап последовательно, начиная с первого незавершённого. Зависимости этапа должны быть готовы.
2. До изменения кода прочитай инструкции репозитория, существующие файлы и соответствующий контракт. Не создавай второй механизм для уже решённой задачи.
3. Работай небольшими задачами из этапа. После каждой законченной части обновляй PROGRESS.md: что сделано, какие файлы изменены, что проверено и что осталось.
4. Сохраняй названия сущностей, API и состояний из спецификаций. Если контракт нужно изменить, сначала синхронно обнови спецификацию и всех его потребителей.
5. Не заменяй выбранные технологии. Не добавляй Redis, Reverb, Kafka, Celery или отдельный Python HTTP backend без новой обоснованной потребности.
6. Не отмечай этап готовым, если работает только интерфейс, используются фиктивные успешные ответы или не пройдены его критерии.
7. Различай «проверено на реальном сервисе», «проверено с заглушкой» и «не проверено». Недоступность LM Studio не мешает независимой работе, но не позволяет объявить интеграцию готовой.
8. Пользовательские правки и исходники сохраняются. Не переписывай весь проект и не удаляй данные ради прохождения проверки.
9. Если не хватает информации для отдельного профиля модели, пометь этот профиль как непроверенный и продолжай независимые этапы. Не выдумывай совместимость.
10. При противоречии сначала учитывай последнее указание пользователя; затем этот файл и тематическую спецификацию. Зафиксируй обнаруженное противоречие и решение в PROGRESS.md.

Короткая постановка для продолжения:
«Прочитай PLAN.md, docs/plan/PROGRESS.md и первый незавершённый этап STAGES.md. Реализуй его по указанным контрактам, выполни его проверки и запиши результат. Не отмечай непроверенное готовым».

## 2. Назначение и объём

Приложение открывается в браузере на http://localhost:7676 и готовит изображения и TXT-подписи для обучения LoRA.
Библиотека содержит много персонажей: ориентир — 500 исходных изображений на коллекцию, несколько тысяч во всей библиотеке.
Пользователь загружает изображения, проверяет результаты анализа, получает предложенный набор, редактирует кадры и подписи, публикует версии и экспортирует папки/ZIP.

Основной сценарий — LoRA одного персонажа. Предусмотреть стратегии подписей для персонажа, одежды и стиля, но первым проверить сценарий персонажа.
Приложение не запускает обучение LoRA. Поддержка семейства модели означает подготовку датасета и, при проверенной совместимости, конфигурации тренера.

Целевые семейства: FLUX.1, FLUX.2 dev/Klein 4B/9B, FLUX.3 Image Klein, Z-Image Turbo и Qwen Image.
Точные чекпойнты, версии тренеров и степень проверки хранятся в реестре профилей.
Qwen Image Edit и обучение редактированию изображений требуют иной структуры данных и не входят автоматически в поддержку Qwen Image.

Все изображения обрабатываются локально. Основной внешний по отношению к Compose сервис — LM Studio на компьютере пользователя.
Облачная обработка и автоматическое скачивание больших моделей не входят в обычный рабочий процесс.

## 3. Зафиксированные решения

| Область | Решение |
| --- | --- |
| Frontend | Vue 3, TypeScript, Vite, Vue Router, Pinia |
| Основной backend | Laravel/PHP; REST API, данные, авторизация локальной сессии, ревизии и задания |
| Обработка изображений | Python worker с исходящими запросами к Laravel и LM Studio |
| База данных | PostgreSQL; изображения хранятся в файлах |
| Realtime | Node.js, TypeScript, Fastify, Socket.IO; отдельный сервис |
| Развёртывание | Docker Compose в WSL2/Docker Desktop, Nginx как единая точка входа |
| Очереди | PostgreSQL: ProcessingJobItem для Python, штатная database queue Laravel для PHP-работ |
| Доставка событий | Отдельная таблица OutboxEvent, публикация Laravel → Fastify по внутреннему HTTP |
| LM Studio | На Windows; URL, необязательный токен и модель задаются в интерфейсе |
| GPU | RTX 4070 Ti Super 16 GB; один общий слот vision/GPU для задач приложения |
| Владельцы данных | Laravel меняет БД и публикует файлы; Python создаёт результаты попыток; Node доставляет события |

Версии PHP, Laravel, Node, Python, PostgreSQL и библиотек определить на S00 по совместимым поддерживаемым версиям и зафиксировать lock-файлами/образами.
После этого не обновлять их незаметно. Не использовать плавающий latest как гарантию воспроизводимости.

Redis и Kafka не нужны для первой версии. Node не хранит бизнес-состояние, Python не подключается к PostgreSQL напрямую.
LM Studio не является участником транзакций БД и может быть недоступна независимо от остального приложения.

## 4. Неприкосновенные правила

- Оригинальные файлы неизменяемы. Изменение кадрирования, цвета или подписи создаёт новую производную/ревизию.
- Ручные и импортированные подписи защищены от фоновой замены. Генерация на устаревших входах сохраняется как предложение.
- Коллекция исходников, черновик набора, опубликованная ревизия и физический экспорт — разные сущности.
- Опубликованную версию не редактировать на месте. Команда «Редактировать» создаёт новый черновик на её основе.
- Уверенно обнаруженные два и более человека исключаются из набора персонажа. Исправление ложной детекции требует ручного решения с причиной.
- Нулевое число детекций не означает, что персонажа нет. Спорные изображения направляются на проверку.
- Закрепление изображения не обходит технические ошибки и правила исключения.
- Ни один автоматический crop не должен незаметно отрезать важную часть персонажа. Предпросмотр учитывает геометрию тренера.
- Подпись должна относиться к подготовленному кадру. Изменение crop требует повторной проверки подписи.
- Состояние задачи и её событие записываются одной транзакцией в PostgreSQL; доставка события выполняется позже.
- Повтор запроса, события или попытки не должен создавать второй результат или повторно увеличивать счётчики.
- Worker с истёкшей арендой не может публиковать результат и не имеет права записи в каталог принятых артефактов.
- Проценты и ETA вычисляются по измеримым данным. Для неопределимого этапа показываются этап и прошедшее время.
- Один сбой файла не обнуляет успех коллекции. Отказ LM Studio приостанавливает зависимые этапы.
- Ошибка и незавершённый экспорт никогда не показываются как успешное завершение.
- Рекомендация количества изображений — объяснимая эвристика; приложение не обещает оптимальное качество будущей LoRA.

## 5. Сервисы и маршрутизация

| Compose-сервис | Назначение |
| --- | --- |
| gateway | Nginx: Vue, публичное API и Socket.IO; единственный опубликованный порт 127.0.0.1:7676 |
| api | Laravel/PHP-FPM: HTTP-запросы и транзакции |
| app-worker | Laravel database queue: публикация артефактов, экспорт, длительные PHP-операции |
| scheduler | Laravel CLI: короткие периодические операции — outbox, истёкшие аренды, отложенные повторы и очистка |
| python-worker | Декодирование, миниатюры, CV, преобразования и запросы LM Studio |
| realtime | Fastify/Socket.IO: внутренний приём событий и подписки браузера |
| db | PostgreSQL и постоянный volume |
| vite | Только профиль разработки; production Vue собирается отдельным этапом Dockerfile |

Один Laravel-образ используется api, app-worker и scheduler с разными командами запуска.
Публикатор outbox выполняется scheduler как короткий ограниченный по времени цикл; тяжёлые копирования/ZIP в него не помещать.

Публичные маршруты Nginx: /, /api/*, защищённая выдача медиа и /socket.io/*.
Внутренний HTTP listener gateway:8081 доступен только в Compose; через него worker обращается к /internal/* Laravel.
Публичный listener блокирует /internal/* и не проксирует Fastify /internal/events.
Node, PostgreSQL и внутренний listener не публикуют порты на хост.

Vue отправляет изменения через Laravel API и получает уведомления через Socket.IO.
Python сообщает результаты Laravel; Laravel сохраняет состояние и публикует событие через outbox.
Самостоятельная публикация Python в Node не используется: сначала результат должен быть сохранён.

## 6. Хранилище и размещение

Код, БД и рабочую библиотеку держать в файловой системе WSL.
Планируемая структура репозитория:

    src/api/                   Laravel
    src/web/                   Vue
    src/worker/            Python
    src/realtime/          Fastify/Socket.IO
    infra/nginx/                конфигурация gateway
    infra/docker/               Dockerfile и вспомогательные команды
    contracts/                  OpenAPI, JSON Schema, примеры контрактов
    profiles/                   версии профилей датасетов
    docs/plan/                  действующие спецификации
    scripts/                    запуск, диагностика, backup/restore
    compose.yaml
    .env.example

Планируемая структура библиотеки: originals/, attempts/, artifacts/, exports/, staging/, trash/.
Секреты, изображения, кеш моделей и большие результаты не коммитить.
Физические права доступа и порядок публикации определены в DATA_MODEL.md.

Выбор папки в UI означает выбор настроенного корня хранения и относительной подпапки.
Показывать соответствующий путь Windows/WSL. Браузер не получает произвольную запись в файловую систему Windows.
ZIP можно скачать обычным браузерным действием.

## 7. Основной пользовательский процесс

1. Создать коллекцию: имя, тип изображений (фото/рисунки/смешанные), необязательные эталоны персонажа.
2. Импортировать файлы/папку и существующие TXT. Видеть передачу, серверную проверку и ошибки каждого файла.
3. Выполнить дешёвые проверки, найти дубли, посчитать людей, отметить подозрительные кадры.
4. Просмотреть очередь проверки и сравнить варианты рекомендуемого набора.
5. Создать черновик набора, выбрать профиль подготовки и триггер, закрепить важные кадры.
6. Подготовить геометрию и проверить «Как увидит тренер».
7. Описать выбранные изображения через LM Studio или вручную; исправить и защитить подписи.
8. Пройти preflight, опубликовать неизменяемую ревизию и экспортировать папку/ZIP.
9. Для исправлений открыть версию как новый черновик. Переключаться между исходниками, наборами и экспортами.

Пробная группа — 10–20 изображений. Первый сквозной сценарий разработки — 20–30 файлов.
Обработка всей коллекции начинается после понимания результатов пробы; описать всю коллекцию можно отдельной командой.

## 8. Этапы и границы готовности

Подробные действия и проверки находятся в STAGES.md. Порядок обязателен.

| Этап | Результат |
| --- | --- |
| S00 | Среда, версии, структура проекта и журнал решений |
| S01 | Compose, БД, Laravel, Vue и диагностические endpoints |
| S02 | Сущности, ревизии, права хранения, базовое API коллекций/наборов |
| S03 | Надёжные фоновые задания, аренды, публикация файлов и общие ресурсы |
| S04 | Outbox, Fastify/Socket.IO, восстановление Vue и fallback |
| S05 | Импорт, миниатюры, галерея, черновики и защищённые ручные подписи |
| S06 | Ручная подготовка, неизменяемая ревизия и универсальный экспорт |
| S07 | LM Studio, проверка возможностей, генерация и сравнение подписей |
| S08 | Детекция людей, дубли, проверка персонажа и объяснимый отбор |
| S08a | Сегментация полного силуэта, редактор масок и безопасный planner |
| S09 | Проверенные геометрические профили тренеров и расширение экспорта |

S06 — первый работающий ручной маршрут. Это промежуточная версия, ещё не весь согласованный продукт.
Готовность первой полной версии требует S00–S10, включая S08a и S09a, всех P1-требований аудита и приёмочных проверок.
Непроверенные модельные профили остаются явно помеченными; отсутствие одного профиля не блокирует универсальный экспорт.

## 9. Обязательные результаты первой полной версии

- Несколько коллекций по 500 изображений; галерея не загружает все оригиналы в память.
- Просмотр, удаление с восстановлением, исправление описаний и создание новых версий подготовленных наборов.
- Прогресс передачи, проверки, CPU/GPU-очереди, подготовки и экспорта; ошибки с понятным действием.
- Рабочая интеграция с пользовательским URL LM Studio из Python-контейнера.
- Контроль людей и сомнительного сходства персонажа, объяснимый отбор и ручное подтверждение.
- Предпросмотр геометрии, защита оригиналов, ручных подписей и ранее опубликованных датасетов.
- Пары изображение + TXT, manifest, preflight, безопасная публикация папки и ZIP.
- Восстановление после перезапуска worker/Node/Laravel, повторов событий и временного отказа LM Studio.
- Проверенный на реальном компьютере хотя бы один профиль модель/тренер; остальные имеют честный статус.
- Проверенное восстановление БД, библиотеки и зашифрованных настроек из резервной копии.

## 10. Что уточняется измерением, а не догадкой

Оперативная память компьютера; установленные версии LM Studio/Docker; квантование VLM; доступная VRAM; типичные форматы и размеры изображений; точные чекпойнты и тренеры.
До измерения использовать безопасные ограничения из CONTRACTS.md, одну GPU-задачу и универсальный профиль без автоматического crop.
Не выбирать окончательный детектор, embedding-модель и пороги только по названию: зафиксировать сравнение на пробной выборке.
